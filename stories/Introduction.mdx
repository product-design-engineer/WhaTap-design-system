# WhaTap Design System

WhaTap 제품 화면을 만들 때 필요한 모든 것이 여기에 있습니다.
색, 글꼴, 간격 같은 디자인 토큰부터 버튼, 테이블, 사이드바 같은 완성된 컴포넌트까지 — 이 Storybook 하나가 기준입니다.

| 종류 | 수량 | 설명 |
|---|---|---|
| 토큰 | 295 | 색·글꼴·간격·그림자 등 디자인 값 |
| 컴포넌트 | 141 | 버튼부터 페이지 레이아웃까지 |
| 무결성 게이트 | 22 | 규칙을 자동으로 지켜주는 검사 |

### 한 가지 주의

`tokens.css`를 직접 import하지 마세요.
토큰 변수만 들어 있어서 색은 맞는데 레이아웃이 깨집니다.
유틸 클래스, 전역 스타일, 다크 모드는 전부 `style.css` 안에 있습니다.

### 꼭 지켜야 할 두 가지

1. **색을 직접 쓰지 마세요.** `#fff`이나 `rgba()`를 코드에 넣는 대신, 토큰을 참조하세요. 다크 모드가 자동으로 따라옵니다.
2. **컴포넌트를 다시 만들지 마세요.** 비슷한 걸 div로 새로 짜는 대신, 여기 있는 컴포넌트를 prop 조합으로 가져다 쓰세요.

### AI 도구 연결

엔드포인트는 `https://whatap-ds-mcp.vercel.app/mcp`이고, 로컬에서는 `http://localhost:5181/mcp`를 쓰면 됩니다.

## 디자이너라면

### 토큰 고르는 법

토큰은 295개가 있고, 각각 "이 값은 어디에 쓰라고 만들었는지"가 작성되어 있습니다.
숫자나 색 코드로 고르지 말고 **역할**로 고르세요.
예를 들어 "경고를 나타내는 배경색"이 필요하면 `--color-surface-warning`을 쓰면 됩니다.

훑어보기: [Color](/?path=/docs/tokens-color--docs) · [Typography](/?path=/docs/tokens-typography--docs) · [Tones](/?path=/docs/tokens-tones-semantic-intent--docs) · [tokens.json](/design-system/tokens.json)

### 컴포넌트 살펴보기

좌측 트리에서 아무 컴포넌트나 눌러보세요.
항목마다 "언제 쓰는지"와 "언제 쓰면 안 되는지"가 작성되어 있어서, 비슷해 보이는 컴포넌트 중 뭘 골라야 하는지 바로 알 수 있습니다.

### 패턴 문서

화면을 설계할 때 자주 부딪히는 질문들을 정리해 뒀습니다.
[patterns.md](/design-system/patterns.md)에서 인터랙션 패턴(삭제 확인, 완료 통보, 즉시 반영 vs 폼 제출)과 구현 정책(헤더 높이, 테이블 밀도, 타이포 위계)을 확인할 수 있습니다.

### Figma 연동

현재 Figma와 직접 연동은 없습니다.
이 Storybook이 디자인의 정본이고, Figma로 토큰을 내보내려면 `node scripts/design-export.js dtcg`를 쓰세요.

## 어떻게 구성되어 있나

좌측 트리가 전체 카탈로그입니다. 크게 세 계층으로 나뉩니다.

### Primitives — 가장 작은 단위 (92개)

버튼, 텍스트 입력, 체크박스처럼 혼자서 동작하는 기본 블록입니다.
다른 디자인 시스템 컴포넌트를 안에 포함하지 않습니다.
예: Button, TextField, Select, Modal, Toast, Chip, Switch 등

### Composite — 조합 (43개)

Primitives를 한 단계 조합한 것입니다.
PageHeader 안에 Button이 들어가고, DataTable 안에 TextField가 들어가는 구조입니다.
예: PageHeader, Sidebar, DataTable, FilterBar, ActionMenu 등

### Shell — 페이지 뼈대 (6개)

최종적으로 화면을 완성하는 곳입니다.
사이드바, 헤더, 본문을 한 곳에 조립합니다.
예: DashboardLayout, 페이지 프리셋 A·B·D 등

### 의존 방향

```
Tokens   ←   Primitives   ←   Composite   ←   Shell
```

오른쪽에서 왼쪽으로만 가져다 쓸 수 있습니다.
Primitives끼리, Composite끼리 서로 import하는 건 금지입니다.
이 규칙은 `lint:layers` 게이트가 자동으로 검사합니다.

## 다섯 가지 핵심 규칙

어떤 작업을 하든 반드시 알아야 하는 규칙입니다.
개별 컴포넌트의 세부 주의사항은 각 컴포넌트 문서의 Do/Don't에 있습니다.

### 1. 색 리터럴을 쓰지 않는다

`#fff`, `rgba()`, `bg-white` 같은 색 값을 코드에 직접 쓰지 마세요.
모든 색은 토큰을 통해 참조합니다.
필요한 색이 토큰에 없으면 리터럴을 쓰는 게 아니라 **토큰을 새로 추가하는 것**이 맞습니다.
TypeScript에서 토큰 값을 넣을 때는 `.value`가 아니라 `.cssVar`를 쓰세요.
`.value`는 라이트 모드의 색이 그대로 고정되어 다크 모드가 동작하지 않습니다.

### 2. 컴포넌트를 다시 만들지 않는다

이미 있는 컴포넌트를 div로 새로 짜지 마세요.
헤더, 카드, 테이블, 사이드바 — 전부 여기에 있고 prop 조합으로 쓸 수 있습니다.
직접 만들면 간격, 보더, 애니메이션이 1px 단위로 어긋납니다.
만들려는 것이 이미 있는지 모르겠으면 [Gallery](/?path=/docs/gallery--docs)에서 검색하거나 MCP 도구 `search_components("삭제 확인")`처럼 의도로 찾을 수 있습니다.

### 3. 토큰으로만 스타일한다

색뿐 아니라 간격, 그림자, 보더, 라운드도 토큰을 참조합니다.
`padding: 16px` 대신 `var(--wds-content-py)`, `box-shadow: 0 4px 16px ...` 대신 `var(--shadow-md)`.
토큰을 쓰면 다크 모드 전환이 자동이고, 나중에 값을 바꿀 때 한 곳만 고치면 됩니다.

### 4. 의존 방향을 거스르지 않는다

```
Tokens   ←   Primitives   ←   Composite   ←   Shell
```

오른쪽에서 왼쪽으로만 가져다 쓸 수 있습니다.
Primitives가 Composite를 import하거나, Composite끼리 서로 import하면 안 됩니다.
이 규칙은 `lint:layers` 게이트가 자동으로 검사합니다.

### 5. 변경은 이 저장소에서만 한다

소비자(프로토타입, 시나리오, 제품 코드)가 토큰이나 컴포넌트를 직접 고치면 안 됩니다.
CSS override, monkey-patch, 토큰 값 덮어쓰기 — 전부 금지입니다.
무언가 부족하면 이 저장소에 새 토큰이나 prop을 추가하는 것이 맞습니다.

전체 규칙 22종은 **[Guardrails](/?path=/docs/tokens-guardrails--docs)**에서 볼 수 있습니다.

## 빠른 시작 — 코드 예제

### 대시보드 페이지 만들기

가장 흔한 형태입니다. 사이드바 + 헤더 + 본문으로 구성된 대시보드 페이지입니다.

```tsx
import {
  DashboardLayout, PageHeader, OptionbarPage, DataTable, FilterBar,
} from "@whatap/design-system";

export default function TransactionPage() {
  return (
    <DashboardLayout
      activeProduct="apm"
      header={<PageHeader title="트랜잭션 목록" />}
      main={
        <>
          <OptionbarPage items={[...]} />
          <FilterBar filters={[...]} onFilter={setFilters} />
          <DataTable columns={cols} data={rows} />
        </>
      }
    />
  );
}
```

### 삭제 확인 대화상자

되돌릴 수 없는 동작에는 반드시 확인 대화상자를 띄워야 합니다.

```tsx
<Button tone="critical" size="sm" onClick={() => setConfirm(true)}>삭제</Button>

<Modal open={confirm} onClose={() => setConfirm(false)} size="sm" title="알림 규칙 삭제"
  footer={<>
    <Button variant="basic" onClick={() => setConfirm(false)}>취소</Button>
    <Button variant="contained" tone="critical" onClick={remove}>삭제</Button>
  </>}>
  「CPU 90% 초과」 규칙을 삭제합니다. 되돌릴 수 없습니다.
</Modal>
```

확인 버튼에 "확인"이라고 쓰지 마세요. **동작 이름**(`삭제`)을 쓰세요.
버튼만 보고 누르는 사람이 실수하지 않아야 합니다.
본문에 **무엇이 사라지는지** 구체적으로 적고, 배경 클릭으로 닫히는 기능을 끄지 마세요.
위험한 건 *실행*이지 *취소*가 아닙니다.

## 기계 판독용 카탈로그

소스 코드의 docstring과 CSS 주석에서 자동 생성되는 파일입니다.
규칙을 두 번 쓰지 않기 위해 한 곳에서 유도합니다.

| 파일 | 내용 |
|---|---|
| [components.json](/design-system/components.json) | 컴포넌트별 용도, Do/Don't, props, 코드 예시 |
| [tokens.json](/design-system/tokens.json) | 토큰 295개의 값, 다크 모드 값, 역할, 권장/금지 |
| [guardrails.json](/design-system/guardrails.json) | 자동 검사 게이트 22종 |

### MCP 도구

`https://whatap-ds-mcp.vercel.app/mcp` 엔드포인트로 8가지 도구를 제공합니다.

- `search_components("삭제 확인")` — 컴포넌트 이름을 모를 때 의도로 검색
- `get_component("Modal")` — 코드 작성 전에 Do/Don't와 props 확인
- `search_tokens("경고 배경")` — 필요한 토큰을 의도로 검색
- `get_tokens({tier: "semantic"})` — 토큰 목록 조회
- `list_components` · `get_do_dont` · `get_design_catalog` · `get_preview_url`

> MCP는 배포된 사이트에서 데이터를 가져옵니다. 코드를 머지해도 재배포 전에는 반영되지 않습니다.
